# 计划

目标：DM-32UV 上收发 P25 Phase 1 **常规**语音（直通和中继，明语）。集群和加密不在范围内；加密的通话要能识别出来并静音。

## 步骤

| 步骤 | 内容 | 怎么验证 |
|---|---|---|
| 1 | IMBE 解码器，定点 C（`c/imbe/`）：c0 ~ c7 的纠错和解扰、参数解量化、MBE 合成 | 和 mbelib 逐帧比较参数（基音、清浊音、谐波幅度） |
| 2 | 空中接口的接收（`c/p25/`）：帧同步、状态符号、NID、LDU1 / LDU2 拆帧、链路控制、加密同步、HDU、TDU / TDULC | 自己的发送端编出的帧加随机错误再解；公开的 P25 录音 |
| 3 | 电脑上的整条链：录音 → 符号 → 帧 → 语音 | 和 DSD-FME 等独立的解码器比较（只在电脑上用，不进仓库） |
| 4 | OpenDMR：HR_C7000 原始模式收 P25 符号，接上 1、2，放音 | MMDVM 热点（Pi-Star，P25 模式）低功率发的真实信号；附近的业余 P25 中继 |
| 5 | IMBE 编码器、发射 | 热点或 RTL-SDR + 独立解码器收 DM-32 发的信号 |

步骤 1 和 2 互不依赖。

现状（2026-11）：1–5 都做完了，在两台 DM-32UV 之间和 MMDVM 热点上验证过；还没在业余 P25 中继上实测。

## 已经核对过的参数

| 项 | 参数 | 来源 |
|---|---|---|
| 符号 | 4800 符号/秒，双比特 01 → +3，00 → +1，10 → -1，11 → -3 | |
| 帧同步 | 48 bit：0x5575F5FF77FF | |
| NID | NAC 12 bit + DUID 4 bit，BCH(63,16,23)，再加 1 bit：只有 LDU1、LDU2 是 1（DSD 的表；它不是码字的奇偶校验，随 NAC 变的不是它） | DSD（生成多项式八进制 6331 1413 6723 5453） |
| BCH(63,16,23) | 生成多项式在 GF(64)（x⁶ + x + 1）的根含 α¹ ~ α²²：窄义 BCH，纠 11 bit（Berlekamp-Massey） | 自己算的 |
| DUID | 0x0 HDU，0x3 TDU，0x5 LDU1，0x7 TSDU，0xA LDU2，0xC PDU，0xF TDULC | DSD |
| 状态符号 | 从帧头（同步字第一个双比特）算起第 35、71、107 … 个双比特，和帧的种类无关 | DSD |
| 帧长（含同步和状态） | HDU 396 双比特，LDU1 / LDU2 864，TDU 72，TDULC 216 | DSD，自己算的对得上 |
| HDU | 36 个字 × (6 bit + Golay(18,6) 12 bit)，RS(36,20)：MI 72、MFID 8、ALGID 8、KID 16、TGID 16；再 5 个空双比特 | DSD |
| TDULC | 12 个字 × (12 bit + Golay(24,12) 12 bit)，每个 12 bit 字是两个 RS 符号，RS(24,12)：链路控制；再 10 个空双比特 | DSD |
| Golay(24,12) | 就是 IMBE 的 Golay(23,12)（0xC75）加一个偶校验位；DSD 用 0xAE3 是因为它把位反着排 | DSD 的位序反推 |
| LDU | 1728 bit / 180 ms：9 个 IMBE 帧，中间插 24 个链路控制字（6 bit + Hamming(10,6) 4 bit），第 8、9 帧之间是低速数据 | DSD |
| IMBE 帧 | 144 bit = 72 个双比特，按交织表拆到 c0 ~ c7；c0 ~ c3 Golay(23,12)，c4 ~ c6 Hamming(15,11)，c7 7 bit 不保护 | DSD、mbelib |
| Golay(23,12) | 系统码，生成多项式 0xC75，数据在高 12 位 | mbelib 的表反推 |
| Hamming(15,11) | 校验矩阵行 0x7F08、0x78E4、0x66D2、0x55B1 | mbelib 和 DSD 一致 |
| Hamming(10,6) | 校验矩阵行 1110011000、1101010100、1011100010、0111100001 | DSD |
| PN 解扰 | p(0) = 16 × c0 的数据位，p(n) = (173 p(n-1) + 13849) mod 65536，取最高位；作用于 c1 ~ c6 的 114 bit | mbelib |
| Reed-Solomon | GF(64)，本原多项式 x⁶ + x + 1，生成多项式的根 α¹ ~ α^(n-k)；LC (24,12,13)，ES (24,16,9)，HDU (36,20,17)。先发数据后发校验，先发的符号次数最高；数据位按发送顺序每 6 bit 一个符号（TDULC 也一样，DSD 的“交换”就是为了这个） | DSD |

**已用真实信号确认**（2026-11-11，sigidwiki 的两个公开录音，`py/c4fm_demod.py` 解调，`c/test/p25_cli.c` 解码）：

- Motorola XTS5000 的常规语音（P25-C4FM-VC_IF.wav）：HDU、15 个 LDU1、14 个 LDU2、TDU，NID 全部解出（NAC 293），
  HDU / LC / ES 的 Reed-Solomon 全部通过（明语，组呼 TG 1，源 ID 1），261 个 IMBE 帧没有一个错，声音正常
- 集群控制信道（P25_C4FM-CC_BEE0014C_IF.wav）：54 秒 725 个 TSDU，NID 全部解出（NAC 140）
- 所以 BCH 的方向、RS 的符号顺序、LDU / HDU 的字段位置和交织表都对

**和参照解码器比**（Pavel Yazev 的 imbe_vocoder，GPL，只在电脑上当对照，`c/build.sh ref`）：

- 同一个录音的 261 帧：音量差 0.6 dB，延时 0，频谱包络平均差 3.1 dB；以它为参照，我们的 PESQ 3.11
  （`py/compare_ref.py`）
- THCHS-30 的 10 句（dmr-vocoder 的测试语音）用它的编码器编码，两个解码器各自解码，和原始语音比 PESQ
  （`py/speech_test.py`）：起初**我们 2.82，它 2.96**，听着高音不够：3000 Hz 以上比它低 2.6 dB，250 Hz 以下高 4 dB
- 为 IMBE 重调了两个参数（dmr-vocoder 的是为 AMBE 调的）：清音增益 0.77 → 1.7，高通 120 → 250 Hz：
  **我们 2.960，它 2.957**，高频差 0.1 dB，音量差 0.5 dB 以内。高通 300 Hz（对讲机的 300 ~ 3000 Hz 通带）是 2.981，
  但 250 Hz 以下少了 10 dB，留作电台上实听时的选项
- 还没动的：频谱增强、相位偏移、相位连续的谐波数

还没核对的：

- 低速数据的 (16,8) 码：还没做，发送时校验位填 0
- TDULC：两个录音里都没有
- 状态符号发什么值：现在由调用的人给（测试里用 2）

## 测试信号

没有 P25 电台也能测：

1. 电脑上：自己的发送端编帧，加错误，自己解；再用独立的解码器交叉核对
2. 公开的 P25 录音和 IQ 文件
3. MMDVM 热点（MMDVM_HS + 树莓派，Pi-Star 或 WPSD）在 P25 模式下低功率发真实信号
4. 附近的业余 P25 中继；P25 集群的控制信道（Phase 1 信号，24 小时都在，适合测同步和纠错）
5. 发射做好以后，两台 DM-32 互测
